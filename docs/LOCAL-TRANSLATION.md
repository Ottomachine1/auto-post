# 本地机器翻译（实施中，尚未接入生产页面）

翻译独立于 SiliconFlow 分析和 Agent，不发送翻译请求到付费大模型。
候选引擎为 Argos Translate（https://github.com/argosopentech/argos-translate），
使用 CPU 上的专用机器翻译模型。模型需要首次下载，运行时离线。

`services/translation/server.py` 是仅供内部访问的服务：

- `GET /health` 返回已安装语言和就绪状态。
- `POST /translate` 接受 `title`、`body`、`source`，目标固定为中文。
- 单任务并发、请求大小限制、逐段翻译；不记录正文、不自动下载、不调用云端。
- 缺少语言包、空结果、运行异常返回失败；不能将其作为翻译成功。
- 默认仅监听回环地址。容器部署时只能连接应用私有网络，禁止公开端口。

安装在独立虚拟环境中；先检查依赖与磁盘占用。使用
`install_models.py --sources en` 显式安装英译中包。其他语言通过对应
语言到英语再到中文的已安装模型转换，可能降低质量；缺包时明确待处理。

2026-10-11 实测：应用服务器已安装 CPU 依赖与 en→zh 1.9 语言包。
两条英文新闻样例成功返回中文，模型处理合计 4.55 秒，进程峰值约 411MiB。
“model” 在样例中被译为“模式”，表明专用小模型仍存在术语偏差，页面必须保留
“机器翻译，请核对原文”提示；此测试不能证明所有语言、长文或事实翻译准确。

已实现独立 translate Worker lane、事件原文/译文/状态字段、历史待处理事件调度、
中文查询与页面原文展开；6 项翻译测试通过，API/Worker/前端构建通过。
新增 11 个中文候选来源（总计 87），尚未验证启用。
仍需完成数据库迁移回归、来源逐项验证、常驻服务配置、生产发布与积压观察。
