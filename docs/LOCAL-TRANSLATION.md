# 本地机器翻译

## V2 当前策略：仅手动请求

用户 V2 需求覆盖早期自动补译策略。采集、分页及打开详情不创建翻译任务；旧的自动任务在显式迁移时取消并保留记录，已保存原文和旧译文均保留。

新增 `Translations` 缓存按原文内容 SHA-256、源语言、目标语言和演示模式隔离。修改正文生成新缓存；重复请求复用同一记录和活动任务。Worker 单 lane 执行，状态可查询，连续不可用最多尝试五次后进入失败，可人工重试。中文原文直接复制，不调用翻译服务。

事件卡片、详情及编辑器提供显式按钮。详情可切换原文/译文；编辑器仅在用户选择“使用译文编辑”后替换输入。网络响应跨越内容修改或切换事件时，不把旧译文应用到新内容。

接口：`POST /api/events/{id}/translation`（target）、`POST /api/translations`（title/body/target）、`GET /api/translations/{id}`、`GET /api/translation-languages`。目标菜单来自本地健康检查实际已安装目标语言与 `TRANSLATION_TARGETS` 的交集；默认 zh。服务不可达显示未就绪，不借用 SiliconFlow 翻译。

迁移：PostgreSQL 009；MySQL 显式 `migrate` 增量创建表并记录版本9，不清库。备份工具包含第16张业务表 Translations，也支持旧15表备份按空翻译缓存恢复。

2026-10-11：手动翻译版本 `092ed27` 的完整 CI `38133023587` 通过 PostgreSQL/MySQL 回归、桌面/移动浏览器用例及三个镜像构建，已部署生产 v0.6.4。真实英文事件 `ff5ca4c389d5450b8a12b4bbe409464d` 手动翻译完成，原文保留，再次请求返回同一已完成缓存。公网验收：mysql/connected、live/ok、安全 Cookie、CSRF、分页、来源 CRUD、Agent 12条来源引用通过，自动发布仍暂停。机器翻译存在缩写及术语偏差，必须核对原文。

## v0.6.1 历史记录（自动策略已被上述手动策略取代）

翻译独立于 SiliconFlow 分析和 Agent，不发送翻译请求到付费大模型。
候选引擎为 Argos Translate（https://github.com/argosopentech/argos-translate），
使用 CPU 上的专用机器翻译模型。模型需要首次下载，运行时离线。

`services/translation/server.py` 是仅供内部访问的服务：

- `GET /health` 返回已安装语言和就绪状态。
- `POST /translate` 接受 `title`、`body`、`source`，目标固定为中文。
- 单任务并发、请求大小限制、逐段翻译；不记录正文、不自动下载、不调用云端。
- 缺少语言包、空结果、运行异常返回失败；不能将其作为翻译成功。
- 默认仅监听回环地址。容器部署时只能连接应用私有网络，禁止公开端口。

安装在独立虚拟环境中；先检查依赖与磁盘占用。使用
`install_models.py --sources en` 显式安装英译中包。其他语言通过对应
语言到英语再到中文的已安装模型转换，可能降低质量；缺包时明确待处理。
