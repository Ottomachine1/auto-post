# 全球情报平台架构

## 目标与范围

将新闻、加密文章与授权社交数据转化为可追溯事件，使用模型分析潜在影响，经人工编辑审核后发布。GMGN 风格体现为密集事件流、快捷过滤和右侧上下文解读；不承诺拥有 GMGN 的数据源、覆盖率或延迟。

v0.1 优先完成单服务器、单管理员、低至中等吞吐的可运行闭环。多用户、全量流式采集和大规模模型流水线在后续阶段交付，不把规划目录标记为已实现。

## 数据路径

1. 采集器：读取部署配置中的 HTTPS RSS 列表与 X 查询词；每次 RSS 最多 40 条、X 最多 10 条。默认 60 秒轮询，下限 30 秒。
2. 规范化：保存来源名、来源 ID、标题、正文、原始链接、来源发布时间和采集时间。
3. 持久化：`UNIQUE(source, source_id)` 防止相同来源重复入库。跨来源语义聚类尚未实现。
4. 展示：后台提供 SSE；v0.1 浏览器每 5 秒获取最新 50 条，以暂停、过滤、关注控制信息密度。
5. 模型：管理员按需请求；不可信来源内容只作为模型数据，无工具调用能力；结果缓存，未连接模型不会返回虚构解读。
6. 审核：人工保存草稿，人工执行 approve，审核后可调用 publish。已审核草稿内容不可修改；编辑需创建新草稿，保证审核对应确定内容。
7. 发布：每草稿每渠道先原子创建唯一 delivery；只记录明确返回的远端 ID 为 published。人工渠道标记 manual_required，失败标记 failed，超时与平台 5xx 标记 unknown。
8. 恢复：重启时把 sending 转为 unknown。unknown、failed 与 manual_required 都不自动再次提交；需人工平台核验与后续运维处理，避免超时重发。

## 数据实体

| 表 | 作用 |
| --- | --- |
| events | 原始来源与事件；demo 标记隔离样例与真实数据 |
| analyses | 事件分析缓存与生成时间 |
| drafts | 内容、渠道、来源事件、审核状态、版本与时间 |
| deliveries | 每草稿每渠道唯一状态与远端 ID |
| audit | 创建、分析、采集、审核、发布操作 |
| source_health | 最近一次采集成功/失败与时间 |

事件 ID、来源 ID 去重不是跨平台精确一次投递保证。远端平台不支持幂等键时，结果不确定必须人工确认。发布状态 published 仅代表 API 明确返回成功，不代表内容永久可见或审核通过。

## 页面布局

- 左侧：工作空间、实时情报、关注、发布中心、数据源与渠道、系统架构。
- 顶部：北京时间、运行模式、内容创建入口。
- 状态区：事件数、关注数、待审核草稿、来源状态，避免演示指标冒充实时统计。
- 主区：来源筛选、关键词搜索、来源时间、正文摘要、关注操作。
- 右侧：当前事件原文、来源链接、模型摘要/影响/不确定性、草稿生成。
- 发布中心：草稿内容、审核状态、各渠道结果、人工导出。

## 安全与部署

生产服务必须配置至少 32 字符管理令牌；业务 API 统一认证，令牌不出现在 URL 或浏览器持久化存储。数据库与密钥不入仓库。前端对来源内容与模型输出进行转义，原始新闻 HTML 不作为 DOM 注入。模型不能自行审核或发文。

单 uvicorn worker 管理采集生命周期，避免多个进程重复轮询。容器以普通用户运行，数据库独立卷持久化；Caddy 是唯一外部入口。公开部署必须使用 HTTPS。远程独立前端跨域未开放，生产建议前后端同源，Sites 静态版用于布局预览。

## 扩展架构与路线

| 阶段 | 交付 | 必要前提 |
| --- | --- | --- |
| P0 当前 | 单管理工作台与人工审核闭环 | 服务器网络、域名、API 凭据 |
| P1 采集完整性 | X 分页/游标/配额退避、授权 Truth 数据、来源可信度规则、跨来源聚类 | 平台读取配额与数据许可 |
| P2 队列化 | PostgreSQL、Redis、独立采集/分析/发布 worker、定时草稿任务、失败重试与核验工具 | 明确吞吐量与延迟目标 |
| P3 团队协作 | 登录、RBAC、多用户工作空间、多人审核、平台 OAuth 连接与刷新 | 用户角色、团队策略 |
| P4 完整多平台 | 官方内容 API、平台格式模板、媒体附件、发布回执与删除管理 | 币安/OKX/Truth 官方能力确认 |
| P5 规模化 | 指标、告警、模型预算、历史检索、数据保留、语义搜索、容灾 | 运营预算与数据规模 |

目标可扩展结构为 `apps/web`、`apps/api`、`workers/collector`、`workers/analyser`、`workers/publisher`、`packages/contracts`、`packages/connectors`、`infra`。只有达到队列化阶段才迁移，当前不创建空壳目录冒充实现。
