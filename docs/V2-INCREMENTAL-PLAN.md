# V2.0 增量审计与实施计划

2026-10-11，依据用户提供的《全球情报聚合与 AI 内容发布系统 V2.0 升级需求》。
本文件记录计划，不代表未完成能力已经交付。

## 阶段 1：基础体验与管理

1. 手动翻译：移除 Schedule 自动 enqueue；取消旧自动任务但保留审计与缓存。
   引入按事件/内容哈希/目标语言缓存；卡片、详情、编辑器显式触发，原文默认，
   原译文切换、队列状态、失败重试。目标语言只能选择已安装可用模型，缺包明确显示。
   用户点击才调用；采集、分页、打开详情不得触发翻译。
2. 发布管理：Draft 增加 DeletedAt/ArchivedAt 等生命周期字段；软删除不删除事件、
   版本、投递或平台内容。批量接口使用确定的 ID/版本和筛选快照，数量确认，清空二次确认。
   排队任务需撤销，sending/unknown 先核验；归档/恢复不能绕过审核。
   回收站永久清理只在用户通过 UI 明确确认后执行，审计和投递凭据保留策略另行定义。
3. 主题：启动前恢复偏好，监听系统主题；导航、表单、弹窗、编辑器、Agent 和图表统一 tokens。

证明：采集后无翻译任务；手动缓存命中零服务请求；改原文缓存失效；批量软删/恢复一致；
第三方零删除调用；真实/演示隔离；三种主题持久化与桌面/移动测试通过。

## 阶段 2：统计、过滤与价值评估

1. 添加统计服务/API：1h/24h/7d/30d/自定义范围，按来源、渠道、主题、处理状态聚合。
   未接入渠道显示未接入，不将零样本解释为无事件；无测量指标返回不可用。
2. Analytics 页面展示来源占比、价值趋势、实际主题、情绪、分组跨源首次时间与采样报道数量。
   明确“采样报道量”，不宣称全平台热度；没有分析的情绪归为无法判断。
3. 新增过滤结果、规则、反馈记录；低价值只隔离，可查看和恢复。
   复用指纹、相似度和 GroupId；记录规则/语义/AI/人工阶段及版本。
4. 价值评分持久化五个维度、可配置权重、理由、模型版本和验证状态；缺证据显示待验证。
   预算内仅分析候选高价值/用户请求内容；不对每篇无差别调用 LLM。

证明：聚合对照固定测试数据和真实 SQL；动态主题无写死示例；权重校验/版本/反馈可追踪；
预算与缓存生效；过滤不丢原文；在人工标注样本上报告准确率和样本局限。

## 阶段 3：全局 Agent 与审核发布编排

标准 Tool Registry 封装 search/detail/summarize/insights/compare/sentiment/duplicates/
generate/draft/publish-status/analytics；工具 schema、能力、参数和错误统一。
全局入口与页面上下文附带选中文章/筛选条件，用户可以明确选择上下文。
LLM 计划必须通过工具白名单和参数校验，新闻中的指令不构成授权。
公开发布仅允许明确用户授权、确定草稿版本已人工审核、目标平台具备权限；
发布工具调用既有 QueuePublish，不能直接发送绕过 unknown、限额、幂等与审计。
增加步骤、工具结果、实际用量、可证明的估算成本、取消/超时/恢复显示。

证明：自然语言时间/渠道/主题约束真实传入查询；跨5篇整合保留来源；越权工具拒绝；
未审核/过期版本/重复发送/未知结果拒绝；真实平台验收必须具备授权，不模拟成功。

## 发布与回滚

沿用 codex/dotnet-rebuild、PR2、指定服务器、PostgreSQL 和当前密钥存放方式。
模块分别测试并发布，数据库迁移单独执行；部署前后备份及隔离恢复验证。
兼容旧 API 字段，不清库、不重置生产数据；回滚只回退应用，写入/发布记录必须先核对。
自动发布默认暂停。无 X/Telegram/Truth/OKX 授权时清楚列为待接入。
