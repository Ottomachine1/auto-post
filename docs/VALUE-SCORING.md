# 重要性评分 v1

每条可见情报通过 POST /api/events/scores 批量取得0–100分。输入最多200条、同运行模式、确定事件ID。评分不调用外部模型；复用已有分析中的importance与模型/提示词版本。没有分析时使用明确标注的本地关注词规则。原文、模型分析和原始模型分数保持不变。

初始权重：来源25%、时效20%、潜在影响25%、新颖20%、证据完整度10%。GET/PUT /api/scoring/profile 读取/修改权重，必须总计100且提交当前版本。保存版本和审计。事实核验始终标为待验证，评分不是正确概率。

来源缺少人工评价时使用50分中性先验；每条事件可明确提供来源评价，汇总时加入5条50分先验平滑。没有接入网站访问量或流量服务，traffic=null，不猜测流量。采集可达性、来源优先级、转载量不转换成可信度。人工事件评价用20%的差值修正最终评分，并展示修正值。同事件重复提交更新原评价，不增加样本数；修改前值写审计。

时效：有效来源时间按24小时指数衰减；缺失、估计或未来异常时间中性50分。新颖性依据当前去重组采样数量递减，不当作独立证据或全网热度。证据完整度只检查来源链接、可用发布时间、摘要长度和作者字段；不声称事实成立。关注词规则未经过人工标注集校准，不能作为自动发文授权。

ValueScores保存快照、输入哈希、维度理由、权重版本、算法value-v1、已有模型信息、截至时间和修正值。相同输入同一小时缓存复用；原文、模型、事件组、权重或反馈改变会生成新快照。ValueFeedback保存最新人工评价；审计保留修改证据。迁移011为加法迁移，旧备份缺失这两表按空表导入，旧Settings按默认权重归一化。

前端：事件卡片显示分数；详情展示各维度及人工反馈；系统状态页可调整权重。来源人工评价影响该来源后续计算，不将同媒体多语言报道当成独立事实核验。后续需要标注样本校准、反馈效果评估与来源权重管理页面；当前版本不宣称经过准确率验收。

新增API均沿用管理员权限、CSRF、事务锁与演示/真实隔离。自动发布策略不因评分功能改变。
