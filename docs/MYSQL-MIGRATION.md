# 云 MySQL 迁移与恢复

目标入口为 `223.254.147.136:58343`，独立数据库 `autopost`。3306 是实例内部端口，不是当前可用的公网入口。其他业务库不参与迁移。

用户已授权首次信任当前证书。连接身份策略见 [证书记录](CLOUD-CERTIFICATE-VERIFICATION.md)。密码、连接串、证书固定值仅存服务器私有配置；不在源码中保存。

迁移先在独立恢复库演练，生产 API/Worker 停止后重新备份 PostgreSQL、导出一致性快照、导入空目标库。15 张业务表逐行按 ID 排序，比较序列化字段 SHA-256 和数量；全部匹配后才切换私有配置与 API/Worker。保留旧 PostgreSQL 和切换前配置。自动发布保持暂停。

`export-db` 使用 RepeatableRead 一致性快照，报告直接针对该快照，避免在线导出结束后因后台写入误判。`import-db` 一次读取每表已有键，拒绝覆盖不同业务行，导入后再次逐表核对。Settings 的初始化占位行允许替换。备份 JSON 包含业务正文和会话，必须保存在权限 600 的私有目录。

MySQL 部署使用 `deploy/compose.mysql.yaml`，OAuth、会话密钥沿用原私有卷，数据库没有新增公网监听。`deploy/backup.sh` 根据数据库类型执行备份；云库每日导出一致性 JSON 和逐表报告，保留 7 天。恢复先在空的专用库执行 migrate、import-db、verify-db，通过后再由管理员决定切换。

切换后不可直接启动旧发布进程或覆盖生产库。回滚前先停止写入者，备份云库，核对新增事件、草稿及投递，再将最新业务数据导入专用 PostgreSQL 恢复库并验证。保留的旧 PostgreSQL 是切换时快照，不能当作当前完整数据。
